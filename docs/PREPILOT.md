# 3명 예비테스트 실행 준비

사용자가 직접 참여 가능한 학생 약 3명이 있다고 확인했습니다. **실제 관찰·응답·실시일·성과 수치는 아직 없습니다.** 진행자와 참여자가 아래 절차를 직접 수행해야 실제 테스트가 완료됩니다.

## 바로 사용할 자료

- 배포 후 참여 안내: `/pilot#prepilot`
- [진행자 대본·동의·질문·기록·7일 확인·분석 기준](../public/prepilot-kit/protocol.md)
- [학생에게 전달할 안내 초안](../public/prepilot-kit/invitation.md) — 발송하지 않았습니다.
- [3명 사전/사후·동의 양식](../public/prepilot-kit/participants.csv)
- [6개 직무 체험 관찰 양식](../public/prepilot-kit/observations.csv)
- [3명 후속 확인 양식](../public/prepilot-kit/followup.csv)
- [발견한 문제와 수정 연결 양식](../public/prepilot-kit/findings.csv)

S01은 프론트엔드→백엔드, S02는 데이터→AI, S03은 보안→클라우드/SRE입니다. 여섯 직무를 한 번씩 관찰하는 사용성 점검이며 직무별 우열·적성·학생 전체의 효과를 측정하는 실험이 아닙니다. 약 30~40분은 예상입니다.

## 실제 완료에 필요한 일

1. 진행자가 통합 배포본을 QA 번호로 점검하고 학생별 일정·S번호·관찰 참여 의사를 확인합니다. 분석·후속 연락은 별도 선택입니다.
2. 체험 전에 동일 명확성 질문과 경험을 받고 첫 수정·실행·도움·회고·서버 저장·비교를 관찰합니다. 처음부터 정답을 알려주지 않고 개입 여부를 남깁니다.
3. 같은 사후 질문, 다음 행동과 선택 이유 설명, 막힌 위치를 실제 응답으로 채웁니다. 빈칸은 무응답이며 0·실패로 바꾸지 않습니다.
4. 후속 연락 동의자 전체에게 실시일+7일에 실제 활동 시작을 확인합니다. 미완료자도 포함하고 무응답과 미시작을 구분합니다.
5. 비식별 결과와 문제 요약을 정리하고 재현 가능한 진행/저장 장애부터 수정합니다. 완성된 양식·연락처·학생 원문은 공개 저장소에 올리지 않습니다.

관찰은 재미 여부에 그치지 않습니다. 직무를 알아본 기존 방식, 직접 체험 후 업무 이해가 달라졌는지(없어도 유효 응답), 도움 후 다음 수정할 부분을 찾았는지, 다음 활동 하나와 이유를 자기 말로 설명했는지를 중립적으로 확인합니다. 기술/창의/실용/발표·협업의 심사 배점을 학생 평가나 효과 점수로 바꾸지 않습니다.

## 정식 파일럿과 분리

S01~S03은 예비테스트, P01~P12는 정식 12명 파일럿입니다. 분석 수집은 기본 꺼짐이며 원하면 동의 전에 해당 S번호를 선택합니다. 번호 변경·재동의는 이전 수집 기간을 삭제하므로 변경 시점을 표시합니다.

```sh
node scripts/report-analytics.mjs --since YYYY-MM-DD --until YYYY-MM-DD --cohort prepilot
node scripts/report-analytics.mjs --help
node scripts/generate-prepilot-kit.mjs
```

`prepilot`만 S번호를 집계합니다. 기본 `all`(일반+정식)과 `pilot`은 S번호를 제외하고 `quality.prepilotExcluded`로 누락 수를 표시합니다. `general`에도 S/P는 포함하지 않습니다. QA는 기본 제외이며 `--include-qa`를 줘도 `pilot`·`prepilot` 분모에는 포함하지 않습니다. 분석 비동의 학생은 이벤트 분모에 없고 진행자 양식에서 별도로 셉니다.

CSV는 배정 외 응답이 모두 빈칸입니다. 생성기는 예비테스트 폴더만 갱신하며 실제 응답 파일을 공개 경로에서 편집하지 않습니다. 기존 12명 양식·배정과 목표값은 유지합니다. 세 사람의 결과를 정식 파일럿 성과나 목표 달성으로 합치지 않습니다.
