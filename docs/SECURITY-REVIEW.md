# 보안 검토와 보완

2026-11-23, main `f3888c1`을 기준으로 코드·합성 입력·별도 로컬 서버를 점검했습니다. 운영 서버 공격, 대량 부하, 실제 학생 기록 조회, 비밀키 출력이나 새 외부 전송은 수행하지 않았습니다. 이 문서는 제한된 코드 검토와 회귀 검증이며 침투 테스트 인증이나 보안 보증이 아닙니다.

## 이번에 반영한 보완

### 1. 요청 본문의 조기 제한

기존 `readBody`는 `req.text()`로 전체 요청을 받은 후 문자 길이를 검사했습니다. 작은 합성 스트림에서 앞부분이 이미 한도를 넘었는데도 뒤쪽까지 읽고 취소하지 않는 동작을 재현했습니다. 큰 입력의 메모리 소비가 플랫폼의 수신 한도까지 커질 여지가 있었습니다. 실제 서비스에서 메모리 고갈이나 데이터 유출을 재현한 것은 아닙니다.

UTF-8 스트림을 읽으며 초과 시 남은 스트림을 취소합니다. `Content-Length`는 큰 요청을 빨리 거절하는 보조 수단이며, 없거나 작게 표시해도 실제 바이트·문자 검사를 계속합니다. 기존 한국어·코드 입력의 UTF-16 문자 제한을 유지하고, 디코딩 전 바이트는 그 제한의 4배로 제한합니다. 기존 API의 오류 문구·상태·본문 계약은 유지합니다.

회귀 검증은 길이 헤더 없음/축소, 큰 길이 사전 거절, 분할된 한글·이모지, 잘못된 UTF-8·JSON을 다룹니다. Vercel의 수신 제한이나 네트워크 자체의 대역폭 소비까지 앱 코드로 없애지는 못합니다.

### 2. 응답 보안 헤더

기존 설정에는 외부 프레임 안에서 서비스를 누르게 만드는 클릭재킹을 제한하는 앱 헤더가 없었습니다. 다음을 전체 경로에 추가했습니다.

- `X-Frame-Options: DENY`: 앱 응답을 외부 프레임에 넣는 것을 제한
- `X-Content-Type-Options: nosniff`: 응답의 MIME 형식 추측 제한
- `Referrer-Policy: strict-origin-when-cross-origin`: 외부 이동 시 상세 경로 대신 출처만 전달
- `Permissions-Policy`: 사용하지 않는 카메라·마이크·위치 권한 차단
- CSP의 `object-src 'none'; base-uri 'self'`: 플러그인 객체와 외부 기준 URL 제한

코드 실행기는 의도적으로 opaque-origin `srcdoc`와 Blob Worker를 사용합니다. 이번 변경은 앱 전체의 script-src/nonce 정책을 도입하지 않습니다. 따라서 완전한 XSS 방지 CSP라고 설명하지 않습니다. 기존 실행 프레임에는 별도 `default-src 'none'`·`connect-src 'none'`과 `sandbox="allow-scripts"`가 유지됩니다. 새 정책과 실행기·Next 인라인 스크립트의 전체 호환 검토가 필요한 엄격 CSP는 별도 과제입니다.

### 3. 알려진 의존성 보안 권고 해소

공개 npm 레지스트리의 `npm audit --omit=dev` 결과는 변경 전 **critical 1·high 1, 패키지 2개**였습니다. Next에는 여러 권고가 묶여 있어 취약점 개수와 패키지 개수를 혼용하지 않습니다.

| 패키지  | 이전 → 이번 버전    | 확인한 근거와 앱 관련성                                                                                                                                                                                                                                                                                       |
| ------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Next.js | 16.3.4 → **16.4.6** | 공식 권고에는 `use cache` typed-array RCE, Edge 쿠키 노출 등 특정 기능·런타임 조건이 있습니다. 현재 앱에서 `use cache`, `next/og` ImageResponse, `next/image`, Edge runtime의 직접 사용 흔적은 찾지 못했습니다. 이것만으로 모든 프레임워크 경로가 공격 불가능하다고 단정하지 않고 수정 버전으로 갱신했습니다. |
| Zod     | 3.25.76 → **4.6.7** | 크기가 큰 컬렉션의 원소별 오류 누적으로 자원을 소모하는 권고입니다. 앱은 요청 본문·배열 크기를 제한하지만, 유지보수자의 수정에는 `.max()`보다 앞선 크기 거절도 포함되어 있어 최신 수정 버전으로 갱신했습니다.                                                                                                 |

Zod 4는 enum record의 모든 키를 요구하고 `unknown` 필드의 누락 동작도 바뀝니다. 기존 게임 기록의 일부 직무만 있는 맵과 preview가 없는 이전 실행 결과를 보존하도록 `partialRecord`·`optional`로 명시했습니다. 기존 저장 형식과 콘텐츠 버전은 변경하지 않습니다. 해당 호환 회귀도 추가했습니다. Next가 생성한 AGENTS.md의 제목 수준 변경도 함께 보관합니다.

변경 후 같은 운영 의존성 검사에서 **등록된 권고 0개**입니다. 개발 의존성 전체나 아직 공개되지 않은 취약점이 없다는 뜻이 아닙니다. 이 수치는 검사 시점·잠금파일 기준이며 지속적인 업데이트가 필요합니다.

## 검증 결과

- 독립 보안 브랜치 자동 테스트 **204/204**, 배포 빌드·타입 검사 통과
- 새 요청 본문 제한 4개와 Zod 저장 호환 1개, 기존 저장/AI/분석/경합 회귀 포함
- 별도 로컬 SQLite 서버에서 기본 API·동시 저장/게임·분석·기록 관리·다음 활동의 API 검사 5종 통과. 합성 손님 기록만 만들고 정리
- 별도 Production 빌드의 홈·API 실제 응답에서 위 보안 헤더 확인. DB를 연결하지 않은 Production의 API 503·no-store와 HTTP Origin 변경 요청 거절 확인
- 운영 의존성 audit: critical 1/high 1 → 0
- 통합판은 회고 안내 회귀를 포함해 **205/205** 테스트·빌드·타입 검사 통과. 별도 시험 서버 API 5종도 다시 통과
- 통합된 Next 16.4.6과 보안 헤더에서 실제 브라우저의 백엔드 Worker 실행 5/5 확인, 이전 두 회고와 코드 복원 확인
- 기존에 승인·연결한 AI로 합성 질문 한 건을 보내 실제 검수 힌트·도구 활동을 확인. SQLite QA 원장에서 추정 $0.0013804 정산·남은 예약 0·pending 0 확인. 운영 학생 상태와 분리된 시험 저장소이며 전체 공급자 비용을 뜻하지 않음

## 다음 보안 우선순위

1. 공개 이용이 늘기 전에 Vercel의 요청량 방어와 DB 용량/요청량 경보를 점검합니다. AI 횟수·금액 예산은 있어도 모든 익명 저장 API를 포함한 분산 요청 제한은 아직 없습니다. 쿠키를 새로 발급받는 것을 막는 방어와 구분해야 합니다.
2. 코드 실행기와 Next 렌더링을 포함해 nonce 기반 script CSP를 별도 검토합니다. 현재 최소 CSP를 엄격한 전체 정책으로 오인하지 않습니다.
3. 실제 운영 팀 역할을 정하고 의존성 권고·AI 사용량·정리 실패를 확인할 담당과 대응 절차를 마련합니다. 자동 외부 알림이나 유료 서비스 가입은 이번 범위에 포함하지 않습니다.
