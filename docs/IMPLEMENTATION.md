# 현재 구현 범위

초기 PRD의 세 직무를 프론트엔드, 백엔드, 데이터 분석, AI 엔지니어, 보안 엔지니어, 클라우드/SRE의 여섯 직무로 확장했습니다.

- 시작 전 필수 설문을 제거했습니다. 직무 선택 후 바로 코드 체험으로 진입합니다.
- 하나의 교내 행사 서비스에서 서로 다른 업무를 체험합니다. 모든 과제는 JavaScript로 작성합니다.
- 체험 화면은 코드 수정, 실행 결과 확인, 체험 기록 순서를 표시합니다.
- AI 코치는 공식 과제, 브라우저 실행 기록, 단계별 문법 힌트를 읽는 제한된 도구 루프를 사용합니다.
- 데스크톱에서는 과제·코드·AI 코치를 나란히 배치하고, 모바일에서는 순서대로 표시합니다.
- 화면의 활동 기록은 실제 도구 실행 결과로만 구성합니다. 모델의 내부 추론은 표시하지 않습니다.
- 모델은 사용자 코드를 직접 변경하거나 배포하지 않습니다. 다음 실행은 사용자가 선택합니다.
- Next.js + Vercel + Neon으로 배포합니다. 이전 Sites/Cloudflare 버전과 별도 프로젝트입니다.
- 익명 쿠키 기반으로 기록을 이어갑니다. 로그인·기기 간 동기화는 출시 범위에 포함하지 않습니다.

## 이슈 #2 우선 보완 (P0-A/B/C)

- 경험·목적은 `null`로 시작하며 사용자가 선택한 값에만 `self_reported` 출처를 부여합니다. 출처 없는 기존 문자열은 `legacy_unverified`로 보존하고 비교·AI의 확정 답변으로 사용하지 않습니다. 회고에서 선택 입력할 수 있습니다.
- 실행 당시 코드 해시·수정 차수·입력·결과·실행 시각을 스냅샷으로 저장하고 회고가 그 실행을 참조합니다. 시작 코드 실행 후 수정만 한 경우와 참고 풀이만 실행한 경우는 완료로 집계하지 않습니다. 직접 수정 후 실행했다면 실패·오류가 있어도 기록할 수 있습니다.
- 실행 근거가 없는 이전 회고는 나의 기록에 보존하며 ‘이전 기록 · 실행 미확인’으로 표시합니다. 확인된 완료 비교에는 포함하지 않습니다.
- AI 대기는 저장 큐·저장 요청·도구 호출 전체에 15초 제한을 적용합니다. 기본 힌트를 누르거나 화면을 바꾸면 진행 중 요청을 취소하고 늦은 응답을 무시합니다. 기본 힌트는 AI 대기 중에도 사용할 수 있습니다.
- P0 당시에는 P1의 미션 버전 고정·추천 규칙·품질 평가·분석 이벤트를 포함하지 않았습니다. AI 품질 후속 보완은 아래와 같습니다.

## 이슈 #2 AI 설명 정확도 (P1-3)

- AI가 자유롭게 작성한 설명을 표시하지 않고, 질문의 목적을 분류하게 하고 서버가 현재 과제의 검수 힌트를 선택합니다. 서버가 허용 목록과 요구사항·확인 항목의 근거를 검증하고 문장·다음 행동·근거를 구성합니다.
- 경계 조건, 문법 오류의 점검 순서, 단계별 힌트, 공식 확인 항목 안내를 여섯 직무에 제공합니다. 화면에 ‘AI가 고른 힌트’와 펼칠 수 있는 과제 근거를 표시합니다.
- 브라우저 보고는 미검증 정보입니다. 알 수 없는 항목과 중복 보고는 제외하고, 보고된 항목 수를 공식 항목 수와 구분해 표시합니다. 통과 수나 원인 진단을 새로 만들지 않습니다.
- 실제 관측한 0점 포함 오안내, 가짜 실행 결과, 전체 정답·적성 판정·비밀키 요청, 잘못된 참조, 6개 직무 경계 조건의 회귀 검증을 추가했습니다.
- 합성 사례 36개로 실제 모델 선택을 별도 평가합니다. [결과](evals/coach-quality-latest.json)와 [평가 기준](AI-QUALITY.md)을 참고하세요. 모의 응답 테스트를 실제 모델의 정확도라고 보고하지 않습니다.
- 과거 AI 대화는 저장·재전송하지 않습니다. 현재 코드·질문·현재 수정 차수의 실행 보고·확인된 프로필만 전송합니다. 회고 내용은 코치 요청에 포함하지 않습니다.
- 분석 이벤트와 파일럿 준비는 아래 후속 변경에서 보완했습니다. 추천 규칙은 아래 후속 변경에서 보완했습니다. 미션 버전 고정은 아래 후속 변경에서 보완했습니다. 힌트 관련성이 모든 질문에서 보장되지는 않으며, 새 과제 조건은 힌트와 함께 검수해야 합니다.

## 질문에 맞는 힌트 선택 후속 보완

- 조건·반환값 질문이 비슷한 확인 항목으로 우회하던 7개 실패를 바탕으로 `rules / syntax / step / check` 의도 분류를 적용했습니다. 과제 내용과 현재 질문을 구분하고, 서버가 검수 힌트·현재 도움 단계·근거를 연결합니다.
- 확인 항목 비교는 명시적인 이름·번호 또는 비교 요청과 연결된 단일한 실패 보고가 있어야 합니다. 임의 항목 선택과 다른 실패 항목으로의 우회를 거절합니다. 브라우저 보고는 계속 미검증 정보로 취급합니다.
- 기존 36개 문항·기대값은 유지하고, 새 표현·실행 비교·문법 오류 부정 등 32개 질문을 추가했습니다. 반복 평가 결과와 코드·문항 해시는 [품질 문서](AI-QUALITY.md)에 기록합니다.
- 자동 회귀 8개를 추가해 총 65개입니다. 기존의 자유 설명 차단·동의·15초 제한·취소 동작은 유지합니다.

## 이슈 #2 P1-1 콘텐츠 버전 유지

- 미션·입력·테스트·기본 힌트·AI 안내를 변경하지 않는 릴리스로 묶고 진행·실행·회고·AI의 참조 버전을 연결합니다. 저장 형식의 `version: 1`과 별도입니다.
- 검토 상태·새 시작 중단·직무별 중단을 관리하며 기존 검수 버전의 이어하기는 유지합니다. 알 수 없는 버전은 최신 기준으로 바꾸지 않고 기록과 다운로드를 보존합니다.
- 기존 진행은 `legacy_baseline`으로 구분해 기존 과제로 이어가며, 과거 실행·회고에는 버전 근거를 소급해 붙이지 않습니다. 기준 미확인 회고는 보존하되 확인된 완료 비교에서 제외합니다.
- 정상 편집 외의 저장 버전 교체·항목 누락과 AI의 버전 불일치를 409로 거절합니다. 별도 데이터베이스 스키마 변경은 필요하지 않습니다.

- 데이터 회고는 수치와 개선안을 함께 적도록 안내합니다. 추천은 외부 AI 호출 없이 동작합니다.
