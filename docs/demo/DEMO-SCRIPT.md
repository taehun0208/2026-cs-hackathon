# 2분 시연 대본

## 시연 준비

- 별도 발표용 브라우저 프로필을 사용합니다. 다른 사람의 체험 기록을 지우거나 덮어쓰지 않습니다.
- 프론트엔드에서 현재 새 체험 `2026-11-23.2`를 시작하고 아래 한 줄을 수정·실행해 회고 하나를 실제로 저장합니다. 회고에는 ‘발표 시연용 QA 기록’이라고 적습니다. 점수는 시연 입력이지 실제 학생 결과가 아닙니다.
- 본 시연은 백엔드의 새 체험에서 시작합니다. 시작 코드의 `attendees.length > capacity`가 그대로 있는지 확인하고 임의로 전체 참고 풀이를 미리 넣지 않습니다.
- AI 전송은 발표자의 합성 코드·질문만 사용합니다. 동의 상태와 연결을 확인하고 개인정보·비밀키를 입력하지 않습니다. 실제 호출 비용이 들며 평가 스크립트를 발표 직전에 대량 실행하지 않습니다.
- 비교할 두 회고가 저장되는지, 다음 활동이 어떤 화면으로 연결되는지 최종 통합 배포에서 확인합니다. 미통합 기능은 이미 동작하는 것처럼 소개하지 않습니다.
- 별도 탭에 발표 자료와 사전 점검 캡처를 열어둡니다. API 응답·사용자 설문·완료 표시를 편집해 성공 장면을 만들지 않습니다.

### 사전 프론트엔드 기록의 한 줄

```js
// 시작 코드
if (availableOnly && !hasRoom) return true;
// 직접 바꿀 줄
if (availableOnly && !hasRoom) return false;
```

### 본 시연 백엔드의 한 줄

```js
// 시작 코드
if (attendees.length > capacity) {
// 직접 바꿀 줄
if (attendees.length >= capacity) {
```

중복 신청 확인이 먼저인 나머지 흐름은 유지합니다. 정원 2명에 이미 2명이 신청한 경우 새로운 신청은 `403`, `accepted: false`입니다. 전체 확인 상황은 다섯 개이며 서비스의 학생 적성 점수가 아닙니다.

### AI 질문

> 신청 인원이 정원과 같으면 어떤 응답을 반환해야 하나요?

실제 응답을 읽고 답합니다. 기대와 다른 검수 힌트를 골라도 성공했다고 말하지 않습니다. 근거 ID는 검수된 과제·확인 항목을 가리키며 AI 내부 사고 과정이 아닙니다.

예산 질문을 받으면 “일 $1·월 $10은 앱의 추정 예약예산입니다. 최대 $0.162144를 먼저 예약하므로 잔액이 있어도 기본 힌트로 전환할 수 있고, 공급자 청구 상한을 보장하지는 않습니다.”라고 설명합니다. 구현과 실제 Neon 동시성 검증을 마쳤으며 운영 반영 여부는 발표 전 문서에서 확인합니다.

### 회고 입력 예시

흥미 4, 체감 난이도 2, 다시 해보고 싶은 정도 4. 메모는 “발표 시연용 QA 기록: 정원과 같은 경계를 바꿔봤어요.”로 입력합니다. 제안되는 실제 활동 중 하나를 고르고 이유는 “조건을 바꾼 뒤 다른 경계도 확인하고 싶어서요.”라고 적습니다. 입력 점수에 따라 추천 후보가 바뀌므로 화면에 없는 후보를 찾느라 시연을 멈추지 않습니다.

## 리허설 확인

두 번 직접 재서 120초 안에 들어오는지 확인합니다. 위 시간표는 계획이며 실측 시간이 아닙니다. 발표자는 스크립트를 읽는 대신 화면에서 바꾼 조건, 실행 결과, 다음 행동을 짚습니다. 팀원별 시연 보조·시간 확인·질문 대응은 실제 담당 합의 후 [역할 양식](TEAM-ROLES.csv)에 적습니다.
