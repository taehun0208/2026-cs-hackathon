# 저장 상태·기록 관리

이슈 #2 P1-4. 마지막 서버 저장 성공 시각, 기기 초안 복구, 전체 삭제, 비접속 자료 정리를 함께 다룹니다.

## 사용자에게 보이는 동작

- 데스크톱 헤더와 모바일 상단에 저장 중·저장됨·저장 실패를 표시합니다. 마지막 성공 시각은 서버가 실제 저장한 시각이며 실패로 갱신하지 않습니다. 나의 기록에서 보관 기한을 함께 확인합니다.
- 수정 사항은 기기 초안에 먼저 쓰고 900ms 뒤 서버에 저장합니다. 기기 저장 실패와 서버 저장 실패를 구분하며, 실패 시 재시도와 JSON 내려받기를 제공합니다. 저장·불러오기·삭제는 응답 본문까지 8초 제한을 적용합니다.
- 새 기록이 없을 때는 ‘새 체험’으로 표시합니다. 새로고침·조회만으로 POST를 보내거나 보관 기한을 연장하지 않습니다.
- 서버 기록이 없거나 만료됐는데 기기 초안이 남아 있으면 체험 편집을 잠시 멈추고 ‘초안 복구해 저장 / 기록 내려받기 / 초안 버리고 새로 시작’을 제시합니다. 자동 재등록하지 않습니다. 복구를 선택하면 저장 성공 시점부터 30일이 새로 시작됩니다.
- 오프라인에서 기존 초안을 계속 편집할 수 있습니다. 서버 기록을 확인하지 못했던 경우 재시도 시 먼저 조회하고, 서버 기록이 없으면 복구 선택을 받습니다. 서버 기록이 있는 경우 확인된 기록과 더 최근의 미저장 직무 초안을 합쳐 저장합니다.
- 기존 v1 기기 초안을 읽을 수 있고, 새 초안에는 마지막 서버 저장 시각·기한·미저장 여부를 별도 포맷으로 보관합니다. 콘텐츠 버전과 `LabState.version`은 바꾸지 않습니다.

## 보관 범위

| 자료                                     | 보관·정리 정책                                                                                                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 서버 체험 상태(코드·실행·회고·사전 응답) | 마지막 성공 저장 후 30일. 기한 이상이면 읽지 않으며 조회 시 해당 만료 행도 정리합니다. 접속이 없어도 일일 작업으로 물리 삭제합니다.                                              |
| 기기 초안                                | 이 브라우저에 남습니다. 전체 삭제 또는 브라우저 데이터 삭제로 제거합니다. 서버 만료와 별개이며 자동 재등록하지 않습니다.                                                         |
| AI 호출 정보                             | 호출 후 30일. 모델·토큰 수·지연·성공 여부와 익명 소유자만 저장하며 코드·질문 원문은 없습니다. 일일 정리 및 전체 기록 삭제 대상입니다.                                            |
| AI 사용 횟수                             | UTC 날짜별 한도. 기록 삭제로 당일 한도를 초기화하지 않습니다. 지난 날짜의 횟수는 다음 일일 작업에서 삭제합니다.                                                                  |
| 선택 분석 이벤트·설정                    | 동의는 기본 꺼짐. 이벤트 수신 후 30일, 설정 마지막 변경 후 30일. 참여 철회 시 이벤트 삭제, 전체 삭제 시 과거 쿠키의 늦은 동의·전송도 차단합니다. [상세 계약](ANALYTICS.md) 참고. |
| 분석 제출 횟수                           | AI 한도와 별도인 UTC 일별 제한. 지난 날짜 행을 일일 정리하며 삭제로 당일 한도를 초기화하지 않습니다.                                                                             |
| 재저장 방지 표시                         | 삭제한 익명 세션 키와 삭제 시각만 최대 30일 + 다음 정리까지 보관합니다. 코드·회고 대신 JSON null을 저장해 예전 세션의 늦은 쓰기를 거절합니다.                                    |

물리 정리는 하루 한 번 실행하므로 정확히 30일 시각에 모든 행이 없어지는 SLA를 주장하지 않습니다. 기한이 지난 체험의 조회 차단과 물리 정리를 구분합니다. 이 정책은 앱의 활성 DB에 적용되며 외부 제공자의 인프라 백업 정책을 변경하는 기능은 아닙니다.

## 삭제와 요청 경합

전체 삭제는 저장·AI 사전 저장과 같은 큐를 사용합니다. 예약된 저장을 취소하고 진행 중 저장 뒤에 DELETE를 실행합니다. 삭제 중 중복 확인·닫기를 막으며 실패 시 초안을 유지합니다. 브라우저 초안 제거까지 성공해야 완료로 표시하고 빈 상태를 자동 저장하지 않습니다.

서버는 먼저 해당 소유자의 분석을 중단·삭제하고, 기존 체험 행을 JSON null로 대체한 뒤 그 소유자의 AI 호출 정보를 삭제합니다. 과거 세션의 저장은 조건부 UPSERT로 409를 반환합니다. 삭제 응답은 새 익명 쿠키를 발급하므로 이후 새 체험은 저장할 수 있습니다. 성공 저장 때만 같은 쿠키의 수명을 30일로 갱신합니다. AI 로그 삽입은 같은 소유자 행을 잠가 삭제와 겹쳐도 늦은 로그를 다시 만들지 않습니다.

같은 출처의 다른 탭에는 기기 초안 제거 이벤트를 전달해 진행 중 응답을 무시하고 새로고침을 안내합니다. 이 기능은 전체 기록의 다중 탭 동시 편집을 병합하지 않습니다. 기기 저장소 자체가 차단된 환경의 탭 간 이벤트는 보장하지 않습니다.

## 예약 정리·배포

`vercel.json`에 `/api/cron/retention`, `0 3 * * *`(UTC 매일 03시, 한국 낮 12시 기준)를 등록합니다. Vercel의 호출 시각은 지연될 수 있으며 실패를 성공으로 표시하지 않습니다. [Vercel Cron 설정](https://vercel.com/docs/project-configuration/vercel-json#crons), [인증·운영 안내](https://vercel.com/docs/cron-jobs/manage-cron-jobs)를 따릅니다.

서버 전용 `CRON_SECRET`이 32자 이상 설정돼 있어야 합니다. 없으면 503, 인증이 다르면 DB 접근 전에 401을 반환합니다. 인증된 요청만 만료 체험·AI 호출·분석 이벤트/설정·지난 UTC 일자의 횟수를 정리하고 익명 총계만 반환합니다. 중복 실행해도 현재 자료는 보존됩니다. 실패는 503이므로 운영 배포 후 Cron 실행 이력을 확인해야 합니다.

Production `CRON_SECRET`은 이전 작업에서 안전하게 설정했으며 예약 설정은 main에 반영돼 있습니다. 값은 코드·로그·문서에 기록하지 않습니다. 이번 develop 변경은 정리 범위에 분석 자료를 추가하며 **main 병합·배포 후 적용**됩니다. 운영 DB 전체 정리는 이번 검증에서 실행하지 않았습니다. 분석 테이블 추가를 위해 `002_analytics.sql`이 필요하고 연결된 Neon에는 적용했습니다. 예약 작업의 실제 실행 이력은 배포 후 별도 확인합니다.

## 검증

- P1-4 당시 자동 테스트 118개(기존 97개 + 저장·복구·삭제·만료·예약 관련 21개), 현재 전체 154개. 분석 정리·삭제·저장 응답 연결도 후속 검증에 포함합니다.
- 저장/조회 시각 및 만료 기한 일치, 조회만으로 기한 미연장, 삭제 후 기존 세션 쓰기 거절과 새 쿠키 저장을 실제 API에서 확인했습니다.
- 실제 Neon에 별도 임시 상태·합성 AI 호출 정보만 만들어 로그 삽입·삭제·늦은 로그 차단·과거 세션 저장 거절을 확인했습니다. 임시 내용은 제거했습니다.
- 별도 SQLite 테스트 서버에서 접속하지 않는 만료 상태·AI 정보·지난 날짜 한도를 인증된 예약 엔드포인트로 정리했습니다. 운영 데이터 전체를 대상으로 실행하지 않았습니다.
- 브라우저에서 모바일 저장 상태, 만료 후 자동 업로드 보류와 복구 선택, 연결 실패 시 초안 보존, 저장소 복구 후 재시도 버튼 성공, 삭제 확인/취소를 확인했습니다. 최종 삭제 동작은 API·큐·저장소 검사로 검증했습니다.

```sh
npm test
npm run build
npm run typecheck
LAB_TEST_URL=http://127.0.0.1:3000 node tests/record-management-api.mjs
LAB_TEST_URL=http://127.0.0.1:3000 node tests/api-smoke.mjs
LAB_TEST_URL=http://127.0.0.1:3000 node tests/next-actions-api.mjs
```

예약 정리 API 검사는 **폐기 가능한 별도 SQLite DB**와 로컬 주소, 테스트 인증값을 명시해야 실행됩니다. 운영 Neon에 연결된 앱에서 실행하지 않습니다.

```sh
LAB_TEST_URL=http://127.0.0.1:3001 \
LAB_RETENTION_TEST_DB=/absolute/path/to/disposable-qa.sqlite \
CRON_SECRET='<local-test-secret>' node tests/retention-api.mjs
```
