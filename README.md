# 해보기 · 2026 컴학 해커톤

컴퓨터학부 학생이 작은 업무를 직접 해보며 다음에 배우고 싶은 직무를 찾는 서비스입니다.

[체험하기](https://haebogi-career-lab.vercel.app) · [개발 PR](https://github.com/taehun0208/2026-cs-hackathon/pull/1)

배포본에서 OpenAI 맞춤 힌트와 Neon 기록 저장이 실제로 동작합니다. 로컬·Vercel 환경의 실제 AI 호출을 검증했습니다.

새 코드 체험은 준비된 코드의 한 줄부터 바꿉니다. 코드 없이 해보는 여섯 직무 게임에는 조작 순서와 구체적인 수정 안내를 제공합니다. 기존 진행은 시작한 버전으로 이어갑니다. [쉬운 체험 범위와 검증](docs/BEGINNER-EXPERIENCE.md)

![직무 선택 화면](docs/screenshots/home.jpg)

설치 없이 직무를 고르고, 준비된 코드를 수정해 실행한 뒤 흥미와 어려움을 기록합니다. 경험·목적은 미응답으로 시작하며 회고에서 선택 입력할 수 있습니다. 두 가지 이상을 체험하면 경험을 나란히 비교할 수 있습니다. 회고 응답에 맞춰 다음 활동과 이유를 제안하며, 직접 고른 활동과 선택 이유를 함께 기록합니다. [추천 규칙](docs/NEXT-ACTIONS.md)을 참고하세요.

## 체험

| 직무           | 작은 업무                               |
| -------------- | --------------------------------------- |
| 프론트엔드     | 신청 가능한 교내 행사 필터 만들기       |
| 백엔드         | 중복·정원 조건에 맞게 신청 처리하기     |
| 데이터 분석    | 취소·중복을 정리하고 참여율 집계하기    |
| AI 엔지니어    | 질문과 관련된 근거 문서 검색하기        |
| 보안 엔지니어  | 로그인·소유권에 따라 접근 권한 확인하기 |
| 클라우드 / SRE | 오류율·지연 시간을 보고 배포 결정하기   |

시작한 과제의 코드·테스트·힌트 버전을 유지합니다. 과제가 갱신돼도 같은 기준으로 이어갈 수 있어요. [콘텐츠 버전과 기존 기록 정책](docs/CONTENT-VERSIONS.md)을 참고하세요.

각 체험에는 시작 코드, 예시 입력, 확인 상황 5개, 단계별 힌트, 참고 풀이가 있습니다. 실제 직무 전체를 재현하거나 적성을 판정하는 서비스는 아닙니다. 같은 JavaScript 문법으로 핵심 로직을 비교합니다.

## 체험 개선 참여·학생 파일럿

도움말과 게임에서 활동 요약 수집을 선택할 수 있습니다. 기본값은 꺼짐이며 AI 동의와 별개입니다. 코드·질문·회고 원문은 분석 데이터에 넣지 않고, 참여를 끄면 해당 분석 기록을 삭제합니다. [동의·30일 보관·집계 방법](docs/ANALYTICS.md)

`/pilot`에는 12명 배정, 진행 안내와 사전·사후·관찰·7일 확인용 빈 양식이 있습니다. 현재는 준비 단계이며 학생 실험 결과는 없습니다. [파일럿 진행 자료](docs/PILOT.md)

## AI 코치

사용자가 동의하고 질문을 보냈을 때만 서버에서 OpenAI API를 호출합니다.

1. `read_mission`으로 공식 요구사항과 검수된 힌트 목록을 읽습니다.
2. `inspect_checks`로 공식 입력·기대값과 브라우저의 참고용 실행 보고를 확인합니다.
3. AI가 질문의 목적(조건·문법·다음 단계·실행 비교)을 분류하면 서버가 검수된 힌트를 선택하고 과제 근거와 다음 행동을 표시합니다. 모델이 작성한 설명은 표시하지 않습니다. 과제 근거는 화면에서 펼쳐볼 수 있습니다.
4. 사용자가 코드를 수정하고 다시 실행합니다.

![AI 코치 활동과 다음 행동](docs/screenshots/ai-coach.jpg)

도구 호출은 최대 3회 요청 안에서 끝나며, 저장을 기다리는 시간까지 합쳐 15초가 지나면 기본 힌트로 이어갑니다. 기본 힌트를 직접 선택하면 진행 중 AI 요청을 취소합니다. AI는 코드를 서버에서 실행하지 않습니다. 브라우저가 보낸 실행 결과는 검증되지 않은 참고 자료로 구분합니다. 형식·근거 오류, 연결 실패·사용 한도 초과·미동의 시 기본 힌트를 표시하며 AI 응답으로 표시하지 않습니다. 코드와 질문은 합계 20,000자 이내로 제한합니다.

모델이 조건을 바꾸거나 실행 결과를 지어내는 일을 막기 위해 자유 설명 대신 질문 의도에 맞춰 검수 힌트를 선택하는 방식을 사용합니다. 특정 확인 항목 비교는 질문이나 유효한 실행 보고에서 대상을 찾을 수 있을 때만 허용합니다. 새로운 오류 원인을 자유롭게 설명하는 범위는 줄어들며, 질문과 맞는 힌트를 선택하는 품질은 별도로 평가합니다. 과제 조건을 변경할 때 힌트와 근거도 함께 검수해야 합니다.

## 실행

Node.js 24 환경에서 실행합니다.

```sh
npm ci
npm run dev
```

기본 주소는 `http://127.0.0.1:3000`입니다. DB 설정이 없는 로컬 개발에서는 `.local/lab.sqlite`를 사용합니다. 실제 배포에는 Neon이 필요합니다.

`.env.example`을 참고해 비밀 설정을 **Git에서 제외된 `.env.local`** 에 준비합니다. 실제 키나 DB 주소를 소스에 넣지 않습니다.

```sh
npm run db:migrate
npm test
npm run typecheck
npm run build
```

## 배포

Vercel의 Next.js 프로젝트에 Neon 저장소를 연결합니다. 마이그레이션은 연결된 DB를 대상으로 한 번 실행합니다.

| 서버 환경 변수   | 용도                                   |
| ---------------- | -------------------------------------- |
| `DATABASE_URL`   | Neon 연결 주소 (`POSTGRES_URL`도 지원) |
| `OPENAI_API_KEY` | OpenAI 서버 전용 API 키                |
| `OPENAI_MODEL`   | 기본값 `gpt-4.1-mini`                  |

```sh
vercel link
vercel --prod
```

브랜치는 `develop`에서 작업하고 PR 검증 후 `main`에 병합합니다. `main`이 배포 기준이며 Vercel GitHub 연동으로 자동 배포합니다.

현재 연결한 API 키는 선택한 설정에 따라 30일 후 만료됩니다. 계속 운영하려면 만료 전에 Vercel의 서버 비밀 설정을 교체해야 합니다.

실행한 코드의 해시·입력·결과·시각·콘텐츠 버전을 회고에 연결합니다. 참고 풀이만 실행한 경우는 완료로 세지 않으며, 이후 직접 수정하고 실행하면 정상 기록할 수 있습니다. 기존 회고는 보존하고 실행 근거가 없으면 미확인으로 구분합니다.

## 데이터와 실행 경계

- HttpOnly 쿠키로 브라우저별 기록을 구분합니다. 별도 로그인이나 기기 간 동기화는 없습니다.
- 기록은 Neon에 저장하고 브라우저에는 초안을 보관합니다. 서버 체험 기록은 마지막 저장 후 30일간 유효하며 만료 자료와 AI 호출 정보는 일일 작업으로 정리합니다. 마지막 저장 시각·기한·실패 재시도와 명시적 초안 복구를 제공합니다. [보관·삭제·배포 정책](docs/RECORD-MANAGEMENT.md)을 참고하세요.
- 학습자 코드는 별도 출처의 iframe과 Worker에서 실행합니다. 네트워크 접근을 막고 3초가 지나면 종료합니다.
- AI에 코드·질문·실행 기록·선택한 경험 수준을 전송합니다. 전송 동의는 서버에서 재확인합니다.
- 하루 최대 브라우저당 22회, 직무당 6회, 전체 200회의 AI 작업을 허용합니다. 이는 결제 금액 한도를 보장하지 않습니다.
- AI 사용 기록에는 모델, 토큰 수, 지연 시간, 성공 여부만 저장합니다. 코드·질문·키는 로그에 남기지 않습니다.
- 공개 서비스 운영 전에는 계정 기반 사용 제한과 사용량 관리가 추가로 필요합니다.

## 검증

```sh
npm test
npm run typecheck
npm run build
LAB_TEST_URL=http://127.0.0.1:3000 node tests/api-smoke.mjs
LAB_TEST_URL=http://127.0.0.1:3000 node tests/record-management-api.mjs
LAB_TEST_URL=http://127.0.0.1:3000 node tests/next-actions-api.mjs
LAB_TEST_URL=http://127.0.0.1:3000 node tests/analytics-api.mjs
```

단위 검증은 과제 풀이, AI 도구 루프·오류 처리·동의·사용 한도, 저장 만료와 사용자 분리를 포함합니다. API 확인은 전용 임시 기록만 생성·삭제합니다. 실제 AI 연결 테스트는 `LAB_TEST_URL=<주소> node tests/live-ai-smoke.mjs`로 별도 실행하며, 모의 응답 검증을 실제 호출 성공으로 취급하지 않습니다.

- 초기 PRD: [Markdown](docs/PRD.md) · [PDF](docs/PRD-initial.pdf) · [Word](docs/PRD-initial.docx)
  실제 모델의 힌트 선택 평가는 자동 테스트와 분리합니다. 기존 합성 사례 36개(직무별 경계·빈 결과/우선순위·미완성 코드·문법 오류·정답 요구·지시 덮어쓰기)와 추가 질문 32개로 평가하며, 기본 힌트로 전환한 응답은 AI 선택 성공으로 세지 않습니다. 실제 호출 비용이 발생하고 기존 사용자 DB는 사용하지 않습니다.

```sh
node --env-file=.env.local scripts/eval-coach.mjs --live --repeat=2
node --env-file=.env.local scripts/eval-coach.mjs --live --suite=holdout
```
