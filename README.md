# COMPFit

**컴퓨터 직무, 해보고 맞는지 가늠하기**

컴퓨터학부 학생이 작은 업무를 직접 해보고, 자신의 흥미와 어려움을 비교하며 다음에 배울 것을 고르는 직무 체험 서비스입니다.

[서비스 바로가기](https://haebogi-career-lab.vercel.app) · [기획서](docs/PRD-v0.2.md) · [5분 발표 PPTX](deliverables/demo/five-minute/haebogi-5min-team.pptx) · [발표 PDF](deliverables/demo/five-minute/haebogi-5min-team.pdf)

## 해결하려는 문제

직무 소개만 읽어서는 실제로 어떤 일을 하는지, 어떤 과정에 흥미를 느끼는지 알기 어렵습니다. 처음부터 프로젝트 하나를 완성해야 한다면 새로운 분야를 경험하는 부담도 큽니다.

COMPFit은 같은 교내 행사 서비스를 여섯 직무의 작은 업무로 나눕니다. 준비된 코드의 한 줄을 바꾸거나 코드 없는 게임으로 시작하고, 직접 해본 경험을 진로 탐색과 다음 학습의 근거로 남깁니다.

## 사용 흐름

1. **직무 선택** — 궁금한 직무의 코드 체험 또는 게임을 고릅니다.
2. **직접 해보기** — 코드를 수정·실행하거나 상황을 판단하고 해설을 확인합니다.
3. **도움 받기** — 문법 안내, 단계별 힌트, 참고 풀이와 선택 동의 기반 AI 코치를 이용합니다.
4. **기록·비교** — 흥미·어려움·재도전 의향을 기록하고 두 개 이상의 완료한 코드 체험을 비교합니다.
5. **다음 활동 선택** — 회고에 근거한 후보에서 다음 학습과 선택 이유를 직접 남깁니다.

## 여섯 가지 직무

| 직무           | 코드 체험                         | 코드 없는 게임                                 |
| -------------- | --------------------------------- | ---------------------------------------------- |
| 프론트엔드     | 조건에 맞는 행사 목록 필터링      | 화면 크기와 글자 크기에 맞게 버튼 고치기       |
| 백엔드         | 중복·정원을 확인하는 신청 처리    | 표가 중복 발급되는 순서를 찾고 해결책 시험하기 |
| 데이터 분석    | 취소·중복을 정리한 참여율 집계    | 행사 기록에서 세는 기준을 정하고 답 찾기       |
| AI 엔지니어    | 질문에 맞는 근거 문서 검색        | 근거를 보고 봇 답변의 적절성 판단하기          |
| 보안 엔지니어  | 로그인·소유권에 따른 접근 제어    | 요청별 허용·인증 필요·접근 거절 판단하기       |
| 클라우드 / SRE | 오류율·지연 시간에 따른 배포 결정 | 서비스 지표를 보고 배포·대기·롤백 판단하기     |

코드 체험은 JavaScript 기초를 전제로 하며 시작 코드, 예시 입력, 확인 항목, 힌트와 참고 풀이를 제공합니다. 게임 완료·흥미 평가는 코드 체험의 수정·실행·회고 기록과 구분합니다.

## 주요 기능

- **한 줄 수정부터 시작**: 전체 코드를 처음부터 작성하지 않고 작은 변경으로 체험합니다.
- **실제 실행과 회고 연결**: 실행 당시 코드 해시·입력·결과·시각·과제 버전을 기록합니다. 직접 수정한 코드를 실행한 뒤 회고를 남기며, 일부 확인 항목이 실패해도 기록할 수 있습니다.
- **맞춤 AI 힌트**: 질문과 과제 근거를 확인해 검수된 힌트를 선택합니다. 화면에는 실제 도구 활동과 응답 출처를 표시합니다.
- **자동 저장·이어하기**: 서버 저장 상태, 마지막 저장 시각과 보관 기한을 안내하고, 기기 초안·재시도·다른 탭 충돌 복구·JSON 내려받기를 제공합니다.
- **경험 비교와 다음 학습**: 자기 응답과 확인된 회고를 비교하고, 검수된 규칙에 따른 활동 후보·선택 이유를 보관합니다.
- **학생 파일럿 준비**: 3명 예비테스트와 12명 파일럿의 진행 안내·빈 기록 양식을 제공합니다. 실제 학생 실험 결과는 아직 없습니다.

## AI 코치는 어떻게 동작하나요?

사용자가 AI 이용에 동의하고 질문을 보내면 서버가 OpenAI API를 호출합니다.

1. `read_mission`으로 해당 버전의 요구사항과 검수 힌트를 읽습니다.
2. `inspect_checks`로 공식 확인 항목과 브라우저의 참고용 실행 보고를 확인합니다.
3. 모델이 질문 의도를 분류하면 서버가 허용된 힌트와 근거를 검증해 표시합니다.

모델의 자유 설명을 그대로 보여주지 않고 검수된 문장을 사용합니다. 저장 대기를 포함한 전체 요청이 15초를 넘거나 연결·검증·사용 한도 문제가 생기면 기본 힌트로 이어갑니다. 기본 힌트는 AI 응답과 구분합니다.

AI는 학생 코드를 서버에서 실행하지 않습니다. 브라우저 실행 보고도 검증되지 않은 참고 자료로 다룹니다. 자세한 평가 범위는 [AI 품질 문서](docs/AI-QUALITY.md)에 정리했습니다.

## 로컬 실행

**Node.js 24**가 필요합니다.

```sh
git clone https://github.com/taehun0208/2026-cs-hackathon.git
cd 2026-cs-hackathon
npm ci
npm run dev
```

브라우저에서 [http://127.0.0.1:3000](http://127.0.0.1:3000)을 엽니다. 외부 DB와 AI 키 없이도 로컬 SQLite 저장과 기본 힌트로 체험할 수 있습니다.

외부 서비스를 연결할 때만 아래 파일을 준비합니다.

```sh
cp .env.example .env.local
```

| 서버 환경 변수                     | 설정                                                                        |
| ---------------------------------- | --------------------------------------------------------------------------- |
| `DATABASE_URL` 또는 `POSTGRES_URL` | 해당 환경의 Neon 연결 주소. 로컬 개발에서 생략하면 `.local/lab.sqlite` 사용 |
| `OPENAI_API_KEY`                   | 실제 AI 힌트가 필요할 때 설정하는 서버 전용 키                              |
| `OPENAI_MODEL`                     | 기본값 `gpt-4.1-mini`                                                       |
| `AI_DAILY_BUDGET_USD`              | UTC 기준 앱 일 예산. 기본값 `1`, `0`이면 실제 AI 중단                       |
| `AI_MONTHLY_BUDGET_USD`            | UTC 기준 앱 월 예산. 기본값 `10`, `0`이면 실제 AI 중단                      |
| `CRON_SECRET`                      | 운영 예약 정리 인증용 비밀 값. 32자 이상                                    |

`.env.local`은 Git에서 제외됩니다. 실제 키·DB 연결 문자열을 커밋하거나 클라이언트용 `NEXT_PUBLIC_` 변수로 노출하지 않습니다. 앱 예산은 공급자 계정 전체의 청구 상한을 보장하지 않습니다.

## 검증

```sh
npm test
npm run build
npm run typecheck
```

저장·복구·삭제·여러 탭의 동시 변경, 실행 근거, AI 도구와 힌트 검증, 게임 흐름, 회고·추천·분석 동의를 검사합니다. 실제 AI 평가는 별도이며 API 비용이 발생합니다. 실행 방법과 결과는 [AI 품질 문서](docs/AI-QUALITY.md)를 참고하세요.

## 배포·협업

1. Vercel에 저장소를 연결하고 운영 환경의 별도 Neon DB와 서버 변수를 설정합니다.
2. 대상 DB를 확인한 뒤 `npm run db:migrate`로 스키마를 준비합니다. 로컬 SQLite는 자동 준비됩니다.
3. 작업 브랜치에서 변경하고 `develop` 대상 PR로 검증합니다.
4. `develop → main` PR을 병합하면 Vercel Git 연동이 운영 배포를 진행합니다.

Production·Preview의 DB와 키 범위를 구분해 관리합니다. 공개 저장소의 Git 연동 배포와 Vercel 대시보드 멤버 권한은 별개입니다. [팀원 실행·배포 안내](docs/TEAM-DEVELOPMENT.md)에 개인 시연과 권한 오류 확인 방법을 정리했습니다.

## 기록·개인정보

- HttpOnly 쿠키로 브라우저별 기록을 구분합니다. 로그인과 기기 간 동기화는 제공하지 않습니다.
- 서버 체험 기록은 마지막 저장 후 30일간 유효합니다. 만료 자료와 AI 호출 정보는 일일 정리 대상이며, 기기 초안의 복원은 사용자가 선택합니다.
- AI 전송 동의와 활동 분석 참여는 별도입니다. 활동 분석은 기본 꺼짐이며 코드·질문·회고 원문을 수집하지 않습니다.
- 시작한 과제 버전을 유지하고 기준이 확인되지 않은 과거 기록은 구분해 보관합니다.

자세한 정책은 [기록 관리](docs/RECORD-MANAGEMENT.md) · [활동 분석](docs/ANALYTICS.md) · [보안 검토](docs/SECURITY-REVIEW.md)를 참고하세요.
